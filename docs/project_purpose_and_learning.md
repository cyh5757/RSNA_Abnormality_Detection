# 이 대회의 목적과 이 프로젝트에서 가져갈 경험

작성: 2026-10-19. 이 문서는 대회의 공식 목표, 현재 프로젝트에서 확인한 결과, 앞으로 스스로 설명하고 수행할 수 있어야 할 역량을 구분한다. 실험 수치의 기준은 기존 E/S30개와 R01 완료 시점이며, 상세 결과는 [실험노트](followup_experiment_results.md)에 있다.

**프로젝트의 개인 학습 목표:** 여러 MRI 영상과 불완전한 정답을 다루면서, 어떤 변화가 성능에 도움이 되는지 공정하게 비교하고, 그 결과를 재현 가능한 학습·추론 시스템으로 만드는 경험을 쌓는다.

## 1. 대회의 최종 목적은 무엇인가?

### 실제 문제: 무릎 MRI 판독을 지원하는 기술

무릎 MRI에는 인대·반월상연골·뼈 등 여러 구조가 함께 나타나고, 한 검사에서 여러 이상 소견이 동시에 발견될 수 있다. 주최 측은 MRI와 원래 판독 보고서를 함께 제공하여 이상을 안정적으로 식별하고, 보다 일관되고 신속한 진료를 지원하는 모델 개발을 목표로 한다. 영상 판독의 차이와 전문 판독 인력에 대한 접근성도 대회의 배경이다. [RSNA 공식 대회 소개](https://www.rsna.org/artificial-intelligence/ai-image-challenge/knee-mri-ai-challenge)

여기서 우리가 직접 만드는 산출물은 **처음 보는 MRI 검사에서 12개 소견 각각의 존재 가능성을 예측하는 모델**이다. 판독 지원이라는 장기적인 목적과, 이 대회에서 평가하는 기능의 범위를 구분해야 한다. 대회 점수만으로 실제 병원에서 판독 시간이나 환자 예후가 개선됐다고 말할 수는 없다.

### 대회 과제: 검사 한 건 → 12개 점수

| 구분 | 해야 하는 일 |
|---|---|
| 입력 | 한 MRI 검사에 속한 여러 시리즈·2D 슬라이스와 제공된 촬영 정보 |
| 예측 | ACL, MCL, 반월상연골, OA, 관절액, 활막염, 낭종, 골좌상, 골절 등 12개 소견별 점수 |
| 출력 | `StudyInstanceUID` 한 행에 소견별0~1 점수12개를 담은 `submission.csv` |
| 평가 | 각 소견의 ROC AUC를 계산한 뒤 동일한 비중으로 평균한 macro ROC AUC |
| 일반화 목표 | 학습에서 본 검사를 외우는 데 그치지 않고 새로운 검사의 소견을 구별하기 |

여러 소견이 함께 있을 수 있으므로 12개 중 하나를 고르는 분류가 아니다. 공식 제출은 검사별 소견 점수이며, 병변의 박스·분할 마스크·위치 좌표를 제출하는 과제는 아니다. 그러므로 최종 출력 조건을 만족하도록 입력 선택, backbone, attention, loss를 설계한다. [공식 과제·평가·제출 형식](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/overview)

예를 들어 `ACL=0.8, Effusion=0.7`은 두 소견 모두 높은 점수를 받았다는 뜻이다. 이것만으로 손상 위치나 치료 방법을 알 수는 없고, 모델의0.8이 실제80% 빈도와 일치하는지도 별도의 확률 교정 평가가 필요하다. AUC는 주로 순위 구별을 평가하므로 **AUC0.77을 정확도77%라고 해석하지 않는다.**

### 이 프로젝트의 도착점

이번 프로젝트를 잘 마쳤다고 할 수 있는 상태는 다음과 같다.

1. 검사 단위 입력과12개 정답·출력의 관계를 설명할 수 있다.
2. 같은 평가 조건에서 기준 모델보다 개선된 구성을 찾고, 어떤 소견에서 좋아지거나 나빠졌는지 설명한다.
3. 개선 원인에 대한 증거와 아직 확인하지 않은 가설을 구분한다.
4. 다른 사람이 정해진 환경·입력·가중치로 제출 파일을 재생성할 수 있다.
5. 남아 있는 오류, 검증 한계, 시간·메모리 비용과 다음 실험을 기록한다.

## 2. 지금까지 어떤 경험을 쌓았는가?

아래는 프로젝트가 제공한 학습 기회와 그 근거다. 실제로 자신의 역량으로 만들려면 코드를 읽고 수정하며 같은 결과를 다시 설명할 수 있어야 한다.

| 역량 | 이번 프로젝트에서 한 일 | 가져갈 수 있는 판단 기준 |
|---|---|---|
| 문제를 학습 문제로 정의 | MRI 검사별12개 독립 출력과 BCE 계열 loss 구성 | 정답의 단위와 출력 형태를 먼저 정해야 한다 |
| 복잡한 입력 전처리 | DICOM 시리즈 정렬, 방향·촬영 조건 분리, 슬라이스 선택, 누락 mask | 입력의 순서·조건·누락을 모델이 구별할 수 있게 표현한다 |
| 전이학습과 모델 비교 | ResNet, DINOv2, Swin, ConvNeXt, ViT 특징 비교 | 사전학습 조건과 데이터 규모를 포함해 후보를 비교한다 |
| 여러 영상의 특징 결합 | 평균/concat, MIL, slice Transformer, RoPE, gate, cross-attention 비교 | 이미지 내부 특징 추출과 이미지 사이 관계 학습을 구분한다 |
| 약한 감독 신호 활용 | 보고서 기반 공개 약라벨로 학습 population 확대, UNK masking | 미상 라벨을 음성으로 처리하지 않고 출처·신뢰도·편향을 추적한다 |
| 실험 설계 | 부모 실험 고정, 한 요소씩 변경, 같은 fold·여러 seed 비교 | 좋아진 결과를 특정 변경의 효과라고 말할 근거를 만든다 |
| 평가와 오류 분석 | OOF, AUC/BCE, 소견별 혼동행렬, 재현율·정밀도, paired bootstrap | 전체 점수와 개별 오류를 함께 보고 불확실성을 인정한다 |
| 모델 개선 | 데이터, 입력 범위, loss, 초기화, 파인튜닝, 앙상블을 분리 | 오류에 맞는 가설부터 시험한다 |
| 실행 자동화 | 학습→버전 고정→오프라인 추론→CSV 검증→다음 실험 | 작업 재개, 버전/파일 검증, GPU 예산도 결과 재현의 일부다 |
| 기술적 의사소통 | 실험노트, 비교표, 전체 코드 Notebook, 자동 shell 작성 | 제3자가 결과와 한계를 판단할 수 있게 근거를 남긴다 |

### A. MRI를 다루면서 배우는 것

일반적인 이미지 분류에서는 한 장과 정답 하나를 묶어 생각하기 쉽다. 여기서는 **검사 하나가 여러 방향·촬영 조건·슬라이스로 구성되고 정답은 검사 전체에 붙는다.** 어떤 슬라이스가 병변을 포함하는지 직접 알려주는 정답이 없는 상태에서 유용한 정보를 모아야 한다.

따라서 “장수를 늘리자”라는 아이디어를 구현할 때도 중심 위치, 이웃 범위, 중복 제거, 물리 좌표, 방향별 누락, 실제 token 수를 함께 확인해야 한다. 이 경험은 여러 시점의 영상, 여러 카메라, 문서 여러 페이지 등 **여러 관측을 모아 하나의 대상을 판단하는 문제**에도 적용해 볼 수 있다. 그 도메인에서 같은 성능을 낸다는 의미는 아니다.

### B. 데이터를 통해 배우는 것

E06→E07은 학습 설정을 유지하면서 약라벨을 추가한 비교다. 평균 OOF AUC가 **0.5860→0.7419**로 올랐다. 모델 구조를 복잡하게 만드는 것보다 감독 신호를 늘리는 변화가 이번 조건에서 더 큰 효과를 냈다.

하지만 공개 보고서 약라벨에는 미상·누락·잘못된 추출이 있을 수 있다. 단순히 표본 수만 세는 대신, 어느 소견의 감독이 부족한지와 어떤 confidence 정책이 적절한지를 살펴보게 된다. 현재 R04/R05는 이 문제를 각각 라벨 신뢰도와 소견별 loss 기여로 나누어 시험한다.

현재 사용한 것은 **공개 자료에서 제공한 보고서 기반 약라벨**이다. 이 프로젝트에서 LLM 라벨 추출 모델을 직접 학습하거나 추출 시스템 전체를 구축한 것은 아니다. 대신 그 결과를 검증·필터링·가중치화하여 영상 학습에 통합하는 경험을 쌓았다.

### C. 모델을 통해 배우는 것

S08 대비 gate인 S10은 **0.7260→0.7400**, cross-attention인 S11은 **0.7364**였다. 이 조건에서는 방향 간 정보 결합이 도움이 됐다. 반면 슬라이스 self-attention이나 RoPE를 넣은 다른 비교에서는 AUC가 하락했다.

여기서 얻을 수 있는 역량은 새로운 모델 이름을 많이 아는 것에 더해, **이 구조가 어떤 정보를 더 표현하고 무엇을 학습해야 하며, 현재 데이터로 그 이득을 얻었는지 확인하는 능력**이다. 같은 attention이라도 입력 token, 위치 정보, pooling, 파라미터 수, 감독 신호가 다르면 결과가 달라질 수 있다.

또한 DINOv2와 ImageNet 모델 비교는 구조뿐 아니라 사전학습 방식·데이터도 다르다. 후보 시스템 비교 결과를 architecture 하나의 순수한 효과로 확대 해석하지 않는 것도 배울 점이다.

### D. 실패한 실험을 통해 배우는 것

S02 이웃5장→S03 이웃10장에서 평균 AUC가 **0.7325→0.7240**으로 하락했다. 그렇지만 MCL·골절·골좌상의 평균 AUC는 상승했다. 따라서 “영상이 많으면 나쁘다”가 아니라 다음 질문으로 이어진다.

- 더 필요한 것은 넓은 범위인가, 같은 범위 안의 촘촘한 관측인가?
- 장수 증가가 모든 검사에서 같은 양의 정보를 추가했는가?
- 일부 소견에 유용한 주변 영상이 다른 소견에서는 오탐을 늘렸는가?
- 차이가 검증 표본58건에서 생긴 변동일 가능성은 얼마나 되는가?

이 질문들이 R02의 범위 확대와 R03의 중심 밀도 증가라는 **구분 가능한 후속 실험**으로 연결됐다. 성능이 떨어진 결과도 다음 선택을 좁히는 근거가 된다. 다만 현재 결과만으로 실제 해부학적 원인을 입증한 것은 아니다.

### E. 점수와 실제 오류를 함께 해석하는 경험

R01은 E09/S13의 고정 앙상블이다. S13 대비 평균 AUC가 **0.7484→0.7714**, seed42의 합산 FN은75→67, FP는144→132로 개선됐다. 하지만 골절 FN은11→13, MCL FN은6→7로 증가했다.

이 사례로 “평균 점수는 좋아졌지만 놓치는 특정 소견은 남아 있다”를 설명할 수 있다. 최종 모델 선택에서 지표 하나를 보고 끝내지 않고, **소견별로 어떤 오류를 감수하는지**까지 확인하는 경험이다. 재현율·정밀도는 임계값0.5에서의 판정 결과이고, AUC는 원래 점수의 순위 성능이라는 차이도 함께 배운다.

위 수치는 같은 Gold58 개발 OOF다. 반복해서 보고 개발한 표본이므로 순위·seed·bootstrap만으로 독립적인 일반화 성능을 증명할 수는 없다. [비교 조건과 원본 결과](followup_experiment_results.md)

## 3. 포트폴리오에서는 무엇을 보여줄 수 있나?

### 프로젝트를 설명하는 문장 예시

> 무릎 MRI 검사에서12개 소견을 예측하는 다중 레이블 분류 파이프라인을 개발·검증했다. 영상 방향·촬영 조건·슬라이스 순서를 반영한 입력과 특징 결합 방식을 비교하고, 공개 판독문 약라벨을 활용해 학습 데이터를 확대했다. 동일 Gold58 OOF 조건에서 소견별 오류를 분석했으며, 고정 앙상블 R01에서 평균 AUC0.7714를 기록했다. Kaggle 학습과 버전을 고정한 오프라인 제출 파일 생성을 자동화했다. 이 수치는 개발 검증 결과이며 임상 성능을 검증한 것은 아니다.

이 문장을 사용할 때는 **본인이 실제로 맡고 이해한 범위**에 맞게 바꾼다. AI 도구의 코드 작성·분석 지원과 공개 Notebook/약라벨의 도움도 구분해서 설명하면 된다. 직접 하지 않은 수작업 라벨링, LLM 구축, 의료 전문가 검토, 독립 임상 검증을 수행했다고 적지 않는다.

## 4. 이것을 내 경험으로 만들기 위한 작은 실습

자동화는 실험을 반복 실행해 주지만, 이해 여부는 별도로 확인해야 한다. 다음을 스스로 해보면 좋다.

1. **검사 하나를 따라가기:** DICOM 파일에서 입력 tensor, Swin 특징, attention 입력,12개 logit까지 shape와 mask가 어떻게 변하는지 코드에서 찾는다. 정답은 어느 단위에 붙는지도 설명한다.
2. **슬라이스 선택을 손으로 예측하기:** 길이40인 시리즈에서 중심5개·이웃5/10을 선택했을 때 어떤 index가 남을지 먼저 적고 `selected_windows` 출력과 비교한다. 중심 간 중복을 확인한다.
3. **한 소견의 평가를 직접 재계산하기:** 저장된 OOF CSV로 외측 반월상연골의 TN/FP/FN/TP와 재현율·정밀도를 계산한다. 임계값을0.3/0.5/0.7로 바꿔 오류가 어떻게 이동하는지 본다. 임계값을 고른 뒤 같은 데이터에서 개선을 입증했다고 주장하지 않는다.
4. **실험 하나의 예상 결과를 미리 적기:** R04가 FP를 줄일지, 희소 소견의 FN을 늘릴지 예상하고 근거를 적는다. 결과를 본 뒤 맞은 부분과 틀린 부분을 따로 기록한다.
5. **독립적으로 한 번 재현하기:** 문서만 보고 제출 Notebook 입력과 완료 버전을 확인해 CSV 생성 경로를 설명한다. 추가 GPU 사용 전에 저장된 결과 재분석부터 재현해도 된다.

스스로 답할 수 있어야 할 핵심 질문은 “왜 이 모델인가?”, “검증 검사가 학습으로 새지 않았는가?”, “왜 전체 AUC 상승과 골절 재현율 하락이 함께 가능한가?”, “실패한 결과가 다음 실험을 어떻게 바꿨는가?”다.

## 5. 무엇을 아직 검증하지 않았는가?

- 전체MRI3D end-to-end 학습, 병변 위치 검출·분할, 영상+텍스트 encoder의 공동 학습은 현재 구현의 성과로 주장하지 않는다. 현재 보고서는 약라벨을 통한 감독으로 사용한다.
- 공개 약라벨 teacher의 gold 독립성, 환자 단위 독립성, 새로운 병원/장비에서의 일반화는 충분히 확인되지 않았다.
- attention 가중치만으로 병변의 실제 위치나 어떤 방향의 인과적 우월성을 증명하지 않는다.
- R04 이후의 성능과 R06 전체 GPU 워밍업/FT 실행 결과는 완료 후 판단한다.
- 이 프로젝트를 통해 의료 영상 ML을 다루는 공학 경험은 쌓을 수 있지만, 임상 판독 전문성이나 실제 배포 적합성이 자동으로 확보되는 것은 아니다.

이 한계를 적는 것은 결과의 가치를 줄이기보다, **현재 근거로 말할 수 있는 범위를 정확히 아는 능력**을 보여준다.

## 6. 대회 성과와 학습 성과의 일정도 구분하기

2026-10-19에 공식 페이지와 Kaggle MCP metadata에서 확인한 정규 제출 마감은 **2026-10-22 23:59 UTC = 10월23일08:59 KST**다. 자동 queue에 기록된 무료 GPU 갱신 예정은 **10월24일09:00 KST**로 그보다 늦다. [공식 대회 일정](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/overview)

따라서 무료 한도 갱신을 기다려 실행하는 후반 실험은 정규 마감 전 제출 후보를 만드는 데 사용할 수 없다. **대회 성과 목표는 마감 전에 완료된 후보를 평가하고 제출 버전을 확보하는 것**, **학습·연구 목표는 이후에도 같은 기준으로 후속 가설을 검증하고 회고를 완성하는 것**으로 나누는 편이 맞다. 추가 실험이 끝날 때까지 기다리는 전략과 정규 제출 일정이 같지 않다는 점을 기록한다.

공식 제출 추론은 Internet OFF, `submission.csv`, CPU/GPU Notebook 최대9시간 조건을 만족해야 한다. 학습 세션의 실행 예산과 공식 제출 추론의 시간 제한을 혼동하지 않는다. 현재 공개 test3건의 CSV 생성 성공만으로 숨겨진 전체 테스트의 시간 제한까지 검증한 것은 아니다. [공식 Code Requirements](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection/overview)

## 7. 남길 회고의 형식

각 주요 실험을 아래 형식으로 한 페이지 안에 기록하면 나중에 다시 설명하기 쉽다.

```text
문제: 어떤 소견에서 어떤 오류가 많았는가?
가설: 그 오류가 생긴 이유를 무엇으로 추정했는가?
변경: 부모 실험에서 무엇 하나를 바꾸었는가?
고정: 데이터/분할/seed/backbone/loss 중 무엇을 유지했는가?
예상: 어떤 지표와 소견이 좋아지거나 나빠질 것으로 봤는가?
결과: AUC/BCE, 소견별 FN/FP, 실행 시간·메모리는 어땠는가?
한계: 우연·선택 편향·라벨 노이즈 등 무엇을 배제하지 못했는가?
결정: 채택/보류/추가 검증 중 무엇을 택하고, 다음에 무엇을 바꾸는가?
재현: config, 데이터/모델 버전, OOF, 실행 명령은 어디에 있는가?
```

이 프로젝트를 통해 남길 핵심 설명은 **“입력과 감독 신호를 설계하고, 오류에서 가설을 만들고, 같은 조건의 실험으로 검증해 다음 결정을 내릴 수 있다”**이다. 모델 이름·순위와 함께 이 과정을 근거로 보여줄 수 있으면 다른 ML 문제를 시작할 때도 활용할 경험이 된다.
